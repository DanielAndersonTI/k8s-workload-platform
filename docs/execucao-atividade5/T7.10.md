## Objetivo

Confirmar que a substituição das réplicas de CPU não interrompe a porta externa 8600 enquanto o cliente envia requisições.

## Comandos

```bash
bash ~/testes-atividade5.sh rollout

# dentro do script
kubectl -n workloads rollout restart deployment/cpu-workload
kubectl -n workloads rollout status deployment/cpu-workload --timeout=180s
```

## O que aconteceu

O laço de 0,2 s acompanhou toda a troca e recolheu 35 amostras, todas com 200. O Deployment subiu as duas réplicas novas antes de encerrar as antigas, que apareceram como `Terminating` ao final. A porta 8600 nunca ficou sem endpoint pronto.

## Saída

```text
cpu: 35 amostras, 0 nao-200
codigos: 200=35
transicoes: t+0s 200
```

## Decisões

O intervalo passou de 1 s para 0,2 s depois da primeira execução, que recolheu apenas 11 amostras em uma troca de 12 s. A amostragem mais densa cobre a janela em que a porta do nó troca de endpoint.

## Problemas

Nenhum. O teste mede disponibilidade, não latência, e por isso não compara média entre as fases.
