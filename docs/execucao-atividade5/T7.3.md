## Objetivo

Registrar CPU e memória após o teste de falha.

## Comandos

```bash
kubectl top nodes
kubectl top pods -n workloads
```

## O que aconteceu

O nó apareceu com 411m de CPU (10%) e 700Mi de memória (8%). Os pods ficaram entre 1m e 37m de CPU e entre 13Mi e 15Mi de memória.

## Saída

```text
minikube 411m 10% 700Mi 8%
cpu-workload-...-s4b9c 37m 13Mi
memory-workload-... 1m 13Mi
```

## Decisões

O pod recém-criado consome mais CPU por causa da inicialização; os demais refletem o perfil ocioso.

Nenhum.
